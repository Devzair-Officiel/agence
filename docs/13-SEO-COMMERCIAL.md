# SEO commercial et architecture sémantique

> Source de vérité du chantier SEO-COM. À lire avant toute intervention sur les pages `/services/**`, `/realisations/**`, `/estimer-mon-projet` et les clusters de ressources prix.

---

## 1. Positionnement SEO

### Mission du chantier

Ce chantier ajoute une couche commerciale orientée intentions de recherche réelles des prospects, sans remplacer les cinq pôles Devzair existants (`/expertises/**`) ni modifier leur positionnement de différenciation.

### Positionnement Devzair inchangé

> Devzair est une agence digitale à taille humaine qui construit des présences digitales complètes pour les entreprises qui veulent être visibles, crédibles et efficaces en ligne.

Ce positionnement ne change pas. Les pages `/services/**` le renforcent par le bas, en répondant aux questions concrètes que posent les prospects avant de choisir un prestataire.

### Angle sur le prix

Devzair n'est pas une agence low-cost. Le sujet du prix est traité avec cet angle :

> Proposer une solution professionnelle proportionnée au besoin et au budget, en expliquant où il est pertinent d'investir et où il est possible de simplifier.

Ne jamais utiliser « pas cher » comme promesse de positionnement. Le mot peut apparaître dans le texte lorsqu'il répond à la question réelle du prospect — il ne doit pas définir l'offre.

## 2. Règles éditoriales humaines

Ces règles complètent les règles générales du projet.

### 2.1 Écrire pour être lu

Chaque texte doit :

- être naturel à la lecture ;
- avoir un rythme agréable ;
- utiliser un vocabulaire professionnel mais courant ;
- pouvoir être lu à voix haute sans sonner artificiellement ;
- apporter une idée identifiable dans chaque paragraphe ;
- répondre à une vraie question du prospect ;
- privilégier la précision aux formules commerciales génériques.

**Test obligatoire avant de considérer un texte terminé** : lecture à voix haute mentale. Si une phrase paraît lourde, artificielle ou trop longue lorsqu'elle est lue, la réécrire.

### 2.2 Ne jamais écrire pour remplir

Interdits :

- paragraphes qui répètent la même idée avec des synonymes ;
- multiplication artificielle de mots-clés ;
- phrases présentes uniquement pour augmenter la longueur du contenu ;
- introductions vagues ;
- conclusions qui ne disent rien ;
- sections artificielles créées uniquement pour atteindre un volume de texte.

Une page peut être plus courte qu'une concurrente si elle répond mieux au besoin.

### 2.3 Éviter le marketing générique

Éviter notamment :

- « Dans un monde de plus en plus digital… »
- « À l'ère du numérique… »
- « Votre présence en ligne est plus importante que jamais… »
- « Nous sommes passionnés par… »
- « Des solutions innovantes adaptées à vos besoins… »
- « Propulsez votre business vers de nouveaux sommets… »
- « Une expérience digitale unique… »
- « Révolutionnez votre présence digitale… »

Ne pas employer « sur mesure », « performant », « innovant », « optimisé », « expertise », « solution » ou « accompagnement » de manière répétitive. Ils peuvent apparaître quand ils décrivent réellement quelque chose.

### 2.4 Préférer le concret

Préférer :

> Votre site doit permettre à un visiteur de comprendre rapidement ce que vous proposez, pourquoi il peut vous faire confiance et comment vous contacter.

plutôt que :

> Nous créons des expériences digitales performantes qui maximisent votre conversion.

Préférer :

> Un site vitrine simple n'a pas besoin de quinze fonctionnalités. Nous commençons par identifier ce qui est réellement utile à votre activité.

plutôt que :

> Nous développons des solutions web innovantes entièrement personnalisées.

### 2.5 Varier le rythme

Ne pas construire tous les paragraphes selon le même patron.

Alterner naturellement : phrases courtes, phrases intermédiaires, explications plus développées quand le sujet le nécessite.

Éviter les successions artificielles de phrases de même longueur.

Éviter que toutes les sections commencent par « Nous… ». Le texte peut commencer par :

- le problème du client ;
- une situation concrète ;
- une question ;
- un constat ;
- une explication.

puis présenter l'intervention de Devzair.

### 2.6 Titres humains et explicites

Un H2 doit annoncer une idée réelle.

| Éviter | Préférer |
|---|---|
| `Notre expertise` | `Ce qui fait réellement varier le prix d'un site internet` |
| `Une solution adaptée` | `Un site vitrine n'a pas besoin des mêmes moyens qu'une boutique en ligne` |
| `Notre approche` (si un titre précis est possible) | Titre qui annonce le contenu réel |

### 2.7 SEO naturel

Pour chaque page :

- définir UNE intention principale ;
- définir des intentions secondaires ;
- utiliser naturellement leurs termes dans le contenu ;
- ne jamais viser une densité de mots-clés ;
- ne pas répéter une expression exacte quand la langue française offre une formulation plus naturelle ;
- employer le vocabulaire réellement utilisé par le prospect ;
- conserver les synonymes et variations naturelles.

Exemple pour « création site internet » — le texte peut employer naturellement :

- création de site internet ;
- création d'un site ;
- site web ;
- site professionnel ;
- site vitrine ;
- projet web ;
- présence en ligne.

Ne pas écrire quinze fois « création site internet ».

### 2.8 Ne jamais inventer de preuve

Règle absolue :

- aucun chiffre inventé ;
- aucun résultat inventé ;
- aucun témoignage inventé ;
- aucun client fictif ;
- aucune ancienneté fictive ;
- aucun volume de trafic fictif ;
- aucun classement Google fictif.

Si un résultat n'est pas mesuré, ne pas le transformer en résultat. Décrire ce qui a réellement été construit ou amélioré.

## 3. Distinction Expertises / Services

### Pages `/expertises/**` — positionnement et différenciation

Les cinq pôles Devzair restent les pages de positionnement et de différenciation de l'agence.

| Pôle | Slug | Rôle |
|---|---|---|
| Concevoir | `/expertises/concevoir` | Stratégie, architecture de l'information, UX |
| Construire | `/expertises/construire` | Développement web, technique |
| Valoriser | `/expertises/valoriser` | Photographie, contenus, identité |
| Visibilité | `/expertises/visibilite` | SEO, référencement, audience |
| Faire évoluer | `/expertises/faire-evoluer` | Maintenance, évolution, suivi |

Ces pages répondent à la question : **comment Devzair travaille-t-il ?**

Elles ne sont pas supprimées, pas renommées, pas modifiées par ce chantier.

### Pages `/services/**` — intentions de recherche commerciales

Les pages services répondent à la question : **de quoi le prospect a-t-il besoin ?**

Elles sont orientées vers les formulations que les prospects utilisent dans les moteurs de recherche, indépendamment de la structure interne Devzair.

| Service | Slug | Intention principale |
|---|---|---|
| Création de site internet | `/services/creation-site-internet` | création de site internet professionnel |
| Site e-commerce | `/services/site-e-commerce` | création site e-commerce |
| Application web métier | `/services/application-web-metier` | développement application web métier |
| Design UI/UX et identité | `/services/design-ui-ux-identite-visuelle` | agence design UX/UI identité visuelle |
| Photographie et contenu | `/services/photographie-creation-contenu` | photographie professionnelle site internet |
| SEO et référencement | `/services/seo-referencement-naturel` | référencement naturel agence SEO |
| Visibilité locale | `/services/visibilite-locale` | référencement local entreprise |

### Pont entre les deux couches

Chaque page service renvoie vers le ou les pôles d'expertise correspondants.

Chaque page expertise renvoie vers les services qui lui sont associés.

Ce maillage croisé est documenté dans la section 6 ci-dessous.

```text
├── /realisations                                  ← (SEO-COM-4)
│   ├── /realisations/kitchen-meat
│   ├── /realisations/nidemiel
│   ├── /realisations/mizan
│   ├── /realisations/haramain-prestige
│   ├── /realisations/al-mumayiz
│   └── /realisations/e-shop-admin                ← si éligible à présentation publique

    ├── /ressources/prix-site-vitrine
    └── /ressources/refaire-site-internet-budget
```

### Règles d'URL

- URL en minuscules, tirets, sans accent.
- URL stables : une URL publiée ne change pas sans redirection 301.
- Aucune page `status: planned` ne doit apparaître dans le sitemap.
- Aucune page ne doit être orpheline (pas de lien entrant depuis une page publiée).

## 6. Règles de maillage

### Flux principal

```text
Accueil
  → /services (hub)
    → /services/{slug} (page service)
      ↔ /realisations/{slug} (preuve)
      ↔ /ressources/{slug} (ressource éditoriale)
      → /estimer-mon-projet ou /contact

Accueil
  → /expertises/{slug}
    → /services/{slug associé}

/realisations
  → /services/{services mobilisés}

/ressources/{article prix}
  → /estimer-mon-projet
  → /services/creation-site-internet
```

### Règles par page

**`/services` (hub)**

Reçoit des liens depuis :
- accueil (navigation principale, corps de page) ;
- footer ;
- breadcrumb de chaque page service.

Renvoie vers :
- toutes les pages services publiées.

**`/services/creation-site-internet`**

Reçoit des liens depuis :
- `/` ;
- `/services` ;
- `/expertises/construire` ;
- `/realisations/kitchen-meat` ;
- articles ressources sur la création de site.

Renvoie vers :
- `/estimer-mon-projet` ;
- `/services/seo-referencement-naturel` (une fois publié) ;
- `/services/maintenance-accompagnement` (une fois publié) ;
- réalisations pertinentes ;
- `/contact`.

**Pages expertises → services**

| Page expertise | Services associés |
|---|---|
| `/expertises/construire` | création site, e-commerce, application |
| `/expertises/concevoir` | design UI/UX, création site |
| `/expertises/valoriser` | photographie, création de contenu |
| `/expertises/visibilite` | SEO, visibilité locale |
| `/expertises/faire-evoluer` | maintenance |

### Règle anti-lien mort

Une page service ne doit être liée depuis une page publiée que si son propre `status === "published"`.

Même règle que pour `/expertises/**` : utiliser un champ `status` dans la config et ne rendre le lien que si `status === "published"`.

## 7. Stratégie réalisations

### Principe éditorial

Une réalisation Devzair n'est pas une vignette de portfolio. C'est une narration du problème, de l'approche et de ce qui a été livré — sans inventer de chiffres, sans forcer des résultats non mesurés.

### Structure d'une page réalisation

1. Contexte et secteur.
2. Problème ou objectif du client.
3. Ce que nous avons pris en charge (services mobilisés).
4. Approche et choix réalisés.
5. Ce qui a été livré (éléments concrets).
6. Ce que la solution permet désormais de faire.
7. Captures d'écran ou visuels autorisés.
8. Liens vers les services correspondants.

### Règle de preuve

- Ne jamais transformer « nous avons créé X » en « X a augmenté les conversions » sans mesure.
- Distinguer résultat mesuré, observation et estimation.
- Un article peut être utile sans chiffre : le contexte, le problème et les choix sont suffisants.

### Priorité de publication

| Projet | Catégorie | Priorité |
|---|---|---|
| Kitchen Meat | Site vitrine restauration | 1 |
| Nidemiel | E-commerce | 2 |
| Mizan | Application / SaaS | 3 |
| Haramain Prestige | Site vitrine conciergerie | 4 |
| Al Mumayiz | Site vitrine B2B | 5 |
| E-Shop Admin | SaaS démonstrateur | À valider (statut à confirmer) |

### Maillage des réalisations

Chaque réalisation renvoie uniquement vers les services réellement mobilisés.

Exemple Kitchen Meat :
- `/services/creation-site-internet` ✓
- `/services/design-ui-ux-identite-visuelle` ✓
- `/services/photographie-creation-contenu` si applicable ✓

## 8. Stratégie éditoriale prix

### Positionnement

Le cluster prix cible les prospects qui cherchent à comprendre les budgets avant de contacter un prestataire. Il ne repositionne pas Devzair comme un acteur low-cost.

L'angle central est :

> Comment construire un site professionnel en maîtrisant son budget ?

### Articles par intention

| Slug | Titre de travail | Intention principale |
|---|---|---|
| `site-internet-pas-cher` | Site internet pas cher : comment réduire le prix sans sacrifier l'essentiel | Capter la recherche à volume élevé sans promettre le low-cost |
| `prix-site-internet` | Prix d'un site internet : ce qui fait réellement varier le budget | Informer sur les facteurs de coût |
| `prix-site-vitrine` | Combien coûte un site vitrine professionnel ? | Intention spécifique site vitrine |
| `refaire-site-internet-budget` | Refaire son site internet : quel budget prévoir et par quoi commencer ? | Intention refonte |

### Règle de publication

Ne pas publier quatre articles faibles simultanément. Commencer par le meilleur article, mesurer les résultats, puis continuer.

### Contenu à couvrir dans les articles prix

- Ce qu'il est possible de simplifier sans compromettre la qualité.
- Ce qu'il vaut mieux conserver.
- Quand un template peut suffire.
- Quand le développement sur mesure devient pertinent.
- Quelles fonctionnalités coûtent réellement du temps.
- Pourquoi les contenus influencent le budget.
- Coût initial versus coût dans le temps.

### Règle sur l'estimateur

Tous les articles prix se terminent par un lien vers `/estimer-mon-projet`.

L'estimateur lui-même doit contenir une partie éditoriale SSR expliquant :
- ce qui influence le prix ;
- pourquoi une fourchette est plus honnête qu'un tarif unique ;
- ce qui permet de réduire un budget ;
- ce qu'il ne faut pas sacrifier.

## 9. Règles Schema.org

### Schemas existants (ne pas modifier sans raison)

| Type | Émetteur | Route |
|---|---|---|
| `Organization` | `useSiteSchema` (layout) | toutes les pages |
| `WebSite` | `useSiteSchema` (layout) | toutes les pages |
| `Service` | `useExpertiseServiceSchema` | `/expertises/**` |
| `BlogPosting` | `useArticleSeo` | `/ressources/**` |
| `BreadcrumbList` | `useBreadcrumb` | pages profondes |

### Schemas à ajouter

#### Pages `/services/**`

- `Service` avec :
  - `@id` : `${url}#service`
  - `provider` : référence `@id` de l'`Organization` globale (jamais de duplication)
  - PAS de `offers`, `price`, `aggregateRating`, `review`, `areaServed` fictif

- `BreadcrumbList` :
  - Accueil → Services → Nom du service

#### Pages `/realisations/**`

- Pas de type Schema.org imposé — à évaluer au cas par cas selon le contenu.
- Si un `CreativeWork` ou `WebSite` est pertinent pour le projet documenté, l'évaluer avec soin.

### Règle générale Schema.org

Ne pas ajouter une propriété parce qu'elle existe dans Schema.org.

N'ajouter une propriété que si :
1. sa valeur est réelle et vérifiable ;
2. elle apporte une information utile aux moteurs ;
3. elle ne crée pas d'attente non tenue (prix, avis, localisation).

### Composable Services

Créer un composable `useServiceSchema` générique utilisable par toutes les pages `/services/**`, sur le modèle de `useExpertiseServiceSchema`. Ne pas dupliquer la logique.

## 10. Règles de validation avant publication

### Contrôles obligatoires pour chaque page service

#### HTML SSR

Dans la réponse serveur, vérifier :

- `<title>` présent et correct.
- `<meta name="description">` présente et non tronquée.
- `<h1>` unique et cohérent avec le title.
- Contenu principal présent (pas uniquement côté client).
- `<link rel="canonical">` correct.
- JSON-LD `Service` et `BreadcrumbList` présents.
- Liens internes vers les bonnes routes.

#### SEO

- Intention principale clairement exprimée dans le H1 et l'introduction.
- Meta description naturelle et non sur-optimisée.
- Pas de doublon de contenu avec une page existante.
- Aucune intention déjà couverte par une page publiée (éviter la cannibalisation).

#### Accessibilité

- Un seul H1.
- Hiérarchie H2/H3 logique.
- Liens avec texte descriptif (pas de « cliquez ici »).
- Images avec `alt` descriptif.
- Test Axe WCAG 2.2 AA sans violation `serious` ou `critical`.

#### Contenu

- Test de lecture à voix haute passé.
- Aucune formulation marketing générique listée en section 2.3.
- Aucun chiffre, résultat ou témoignage inventé.
- Aucun lien vers une route non publiée (`status !== "published"`).

#### HTTP et indexation

- HTTP 200 sur la route.
- Route présente dans le sitemap si `status === "published"`.
- `X-Robots-Tag` absent ou conforme à la politique d'indexation.
- Pas de soft-404.

#### Tests

Pour chaque page service, la suite de tests doit couvrir :

- config typée (unicité du slug, champs requis) ;
- SSR (title, H1, description, canonical en HTML serveur) ;
- Schema.org JSON-LD présent dans le HTML ;
- BreadcrumbList cohérent ;
- liens vers routes publiées uniquement ;
- accessibilité (Axe WCAG 2.2 AA) ;
- responsive (390 / 768 / 1440) ;
- sitemap si applicable.
